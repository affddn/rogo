# What a gateway command does **not** imply

SEA 0.0.163, static client inspection. A defined request is not proof of account permission, an implemented CLI operation, or server acceptance. The [live-check record](../CONNECT.md#live-check) includes a web-initiated campaign start and settlement using the actual local SEA battle engine. Other battle workflows below are based on static inspection unless stated otherwise.

## Battles are workflows

| Player action                            | What the official client does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Challenge a campaign stage               | Sends `StageFightReq` (5001). The 5002 reply supplies a fight ID, seed, round and combat inputs; the client runs the fight. At completion it sends 5003 with the fight ID and statistics; 5004 supplies the result, rewards and stage progress. Opening a fight is not equivalent to earning a clear. Sources: `BossChallengeStageProtoHandler.OnStageFightRes` / `OnStageFightCompleteRes`, `BossChallengeStageAdapterFV.FightEnd`.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Dodge in Baphomet Challenge (World Boss) | 5033 starts the fight and 5035 settles it with damage. The dodge tap adds a QTE option to the running simulation; the settlement includes option types and ticks. There is no dedicated “dodge now” request in this command enum. Sources: `FightView.OnQTE`, `WorldBossStageAdapterFV.FightEnd`, `StageAdapterFVBase.BuildBaseFightStatistic`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Sweep rather than fight                  | A sweep has its own request, not a fabricated settlement: resource dungeon 5011/5017, MVP 5047, Endless Tower 5057, Guild Boss 4477. Eligibility and remaining uses still matter. In `EndlessTowerSweepDialog.OnClickFreeSweep` / `OnClickAdSweep`, the free and ad variants check separate remaining counts; the ad route invokes the SDK before the request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Run a team dungeon                       | Form/join or match; for matchmaking confirm (4321) and handle room notifications (8064/8066/8068). A start (6001) and the start notification (8062) precede a fight-data read (6003) using the team ID. The client simulates with those inputs, then settles that fight (6005). The frame/close notifications 8028/8030 are not client controls or evidence of a separately usable realtime socket. Sources: `TeamMatchConfirmDialog.SendConfirm`, `TeamPVEChallengeDialog.OnClickChallenge` / `OnFightStart`, `TeamPveProtoHandler.OnTeamPveGetFightDataRes`, `TeamPveStageAdapterFV.FightEnd`.                                                                                                                                                                                                                                                                                       |
| Collect online idle income               | The idle scene refreshes `OnlineIdleRewardPreReq` (4087) every 15 s and each kill tick calls `FightRewardModel.TryGetOnlineReward`: up to 4 intervals per `OnlineIdleRewardReq` (4089) with the kills since the last claim; battery-saving mode credits `StageInfoCfg.BatterySavingMob` kills every `BATTERY_SAVING_KILL_MOB_INTERVAL` (15) s instead of fighting. The official client sends `QueryPlayerDataReq` (4005) only at login, on a server day rollover (`LoginModel.PerformCrossDayRefreshAsync`) and from a GM-only path. Live on 11 Nov 2026, every 4005 settled the idle time since the previous settlement as offline income (`offline_idle_info`) and reset the 4087 pending count to 0. The progression job rescans with 4005, so it never sends 4089 (the same window could be paid twice); it reports what each scan settled instead. 4089 is not blocked by policy. |
| Skip an arena fight                      | Do not assume every start needs a separate settle call. 5065 has a sender method, but `ArenaStageAdapterFV.FightEnd` and `FightView.OnClickSkipFight` use the result cached from the start reply (5064) for ordinary arena fights. Replay skip fast-forwards locally. See `ArenaProtoHandler.OpenSettleFromCachedStartRes`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

## Other surfaces

- **Local/UI:** the idle scene builds a local fight report (`IdleStageAdapterFV.BuildFightReport`); that is distinct from claiming idle income on the gateway. Opening a panel or changing an audio/graphics preference isn't automatically an RPC. See `BasicSettingUI`, `GraphicsSettingsDialog`; contrast the actual push-settings request 4725.
- **Commerce:** despite its name, `QueryRechargeCpOrderReq` (4201) opens a payment flow, not a read-only shop lookup. The reply carries the CP order ID; the client builds an order and passes it to SDK payment. Voucher payment (4213) is separate. See `RechargeModel.SendRechargeRequest` and `RechargeProtoHandler.OnQueryRechargeCpOrderRes`. Do not assume gateway access can complete a platform purchase.
- **Publisher SDK / external UI:** sign-in, account center, reviews, support, product lookup, payment, web views, translation and ad playback are SDK surfaces. Survey entry opens a web view; the reward notification is not a “submit survey” request. `SdkManager.PlayRewardAd` checks the feature gate and either an ad-free entitlement or a successful SDK callback before invoking the reward action. See [ISdk](../decompiled/ISdk.cs), `FunctionManager.OpenFunctionView`, `SurveyProtoHandler.OnSurveyRewardChangedNotify`.
- **HTTP vs. gateway:** [VersionServerService](../decompiled/VersionServerService.cs) uses the version service for client params, client version, pre-environment selection, game notice, game-notice version, recommended servers, server list, selected-server status, maintenance notice, and GM password verification. These ten request message types have **no** `ProtoCmd` entry. `PingReq` is another message type without such an ID: the demonstrated gateway heartbeat is 4009, not an inferred ping ID.
- **Operator/test:** the 9xxx GM/debug/test requests are not ordinary player features. `GameSettings.IsGMEntryVisible` gates the UI, and `GMInputDialog` uses separate HTTP verification. A method in a GM screen is not evidence a regular account may use it. Do not misclassify the similarly named 4241 (`QueryGmtMessageReq`): `GmtMessageProtoHandler.OnGmtMessageNotify` schedules that fetch on the normal client.

### Evidence boundary

`GameLogic.Module.NetModule.NetModule` owns one `GameWebSocket`; `WebSocketType` defines None/Gateway in this build. `Proto.ProtoParserRegister.Parsers` maps **all 294 incoming enum entries** (responses and notifications) to their exact parser names and IDs. This does not turn notifications, nested payload variants or internal `GameEvent` numbers into sendable player actions; nor does it inventory every OS, SDK or future hot-update behavior.

Type/method anchors above refer to `bin/GameLogic.dll` under the lookup app (SHA-256 `fed73c201f1f04097b9c44b22bbce3d054e1ece7a5c5e2dd48c233e9e38faa81`). Re-inspect a named type, e.g. `ilspycmd --disable-updatecheck -t GameLogic.TeamPveProtoHandler bin/GameLogic.dll`; use `-t Proto.ProtoParserRegister bin/GameProto.dll` for the parser registry.
